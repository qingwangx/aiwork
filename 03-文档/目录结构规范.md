# 目录结构规范

> 本文是 `F:\AIwork` 的**可执行规范**——每条规则都对应
> `04-脚本/check-structure.sh` 里的一段校验代码。改规范请同步改脚本。

## 一、规则清单

### 硬性规则（违反 = 拦截提交）

| # | 规则 | 校验位置 |
|---|---|---|
| R1 | 顶层 10 个目录必须存在：`00-收件箱` `01-项目` `02-数据` `03-文档` `04-脚本` `05-素材` `06-产出` `07-参考资料` `08-归档` `09-临时` | ① |
| R2 | `02-数据/` 下须有 `原始/` 与 `处理后/` | ② |
| R3 | `05-素材/` 下须有 `图片/` 与 `模板/` | ② |
| R4 | `01-项目/` 下**每个**项目必须有 `src/` `docs/` `data/` `out/` 四个目录 | ③ |
| R5 | `01-项目/` 下**每个**项目必须有 `README.md` | ③ |
| R6 | 所有 `.bat` 文件必须为**纯 ASCII**（连注释也不行） | ⑥ |

> 以 `_` 或 `.` 开头的项目目录会被跳过（用作临时实验区）。

### 软性规则（违反 = 告警，不拦截）

| # | 规则 | 校验位置 |
|---|---|---|
| W1 | 根目录只允许 `README.md` `AGENTS.md` `.gitignore` 及点开头文件 | ④ |
| W2 | 名称不得含空格 | ⑤ |
| W3 | 名称不得含「最终版」「副本」「copy」「未命名」「新建文件夹」 | ⑤ |

## 二、四级护栏

结构靠四层递进的机制保证，越往后越硬：

| 层级 | 机制 | 何时生效 | 能否绕过 |
|---|---|---|---|
| **L1 约定** | `AGENTS.md` | AI 每次会话自动加载 | 能（AI 可能忘） |
| **L2 模板** | `04-脚本/new-project.sh` | 建项目时**唯一入口** | 能（可手建目录） |
| **L3 校验** | `04-脚本/check-structure.sh` | 手动/钩子/CI 调用 | 能（没人跑就不跑） |
| **L4 强制** | pre-commit 钩子 + GitHub Actions | 每次提交、每次推送 | 本地可 `--no-verify`，**CI 不能** |

设计意图：L1/L2 让**正确做法成为最省事的做法**；L3 让问题**当场可见**；
L4 让问题**无法进入历史**。本地能绕、远端不能——这是有意的取舍，
避免钩子误伤紧急提交，但保证 `main` 分支永远合规。

## 三、日常用法

```bash
cd /f/AIwork

# 建新项目（唯一入口，自动合规）
bash 04-脚本/new-project.sh 桥梁监测

# 检查结构
bash 04-脚本/check-structure.sh

# 检查并自动补齐缺失的目录/README
bash 04-脚本/check-structure.sh --fix

# 只看问题
bash 04-脚本/check-structure.sh --quiet
```

提交时钩子会自动跑一遍，结构有错会拦截并告诉你怎么修：

```
  ✗ 提交被拦截：目录结构不符合规范
      ✗ 错误 项目 违规测试 缺少目录: src
      ✗ 错误 项目 违规测试 缺少文件: README.md（项目说明）
  自动修复: bash 04-脚本/check-structure.sh --fix
  跳过校验: git commit --no-verify
```

## 四、Windows 批处理（.bat）约束 —— 重要

**规则 R6：`.bat` 文件必须全 ASCII，注释里也不能有中文。**

### 为什么

cmd.exe 按**控制台代码页**（中文系统是 GBK）解析 `.bat` 的**内容**：

- 文件存成 UTF-8 + 内容含中文 → cmd 按 GBK 解码 → 乱码。
  实测 `type nul > 情况.txt` 会创建出 `鎯呭喌.txt`，找不到目标文件。
- **加 `chcp 65001` 也救不了**：cmd 逐行读取批处理，中途切换代码页会让
  **解析偏移错位**，后面的行被当成垃圾命令。实测报错
  `'?' is not recognized` 和 `'m' is not recognized`。
- 中文**注释**同样触发（`rem 这里是中文` 就会崩）。

### 所以本工作区这样分工

| 层 | 语言 | 说明 |
|---|---|---|
| 目录名、`.bat` 文件名 | 中文 | 文件名由文件系统处理 Unicode，**安全**，方便你双击辨识 |
| `.bat` 文件**内容** | **纯 ASCII** | 只有调用 bash 的几行 |
| **`.sh` 脚本内容** | 中文随意 | bash 处理 UTF-8 可靠；中文提示/输出都写在这里 |
| `.sh` 脚本**文件名** | **ASCII** | 因为要被 `.bat` 内容以纯 ASCII 方式引用 |

这就是 `new-project.sh` / `check-structure.sh` / `install-hooks.sh`
用英文名、而 `新建项目.bat` / `检查结构.bat` 用中文名的原因。

`.bat` 首行 `chcp 65001` 是为了让 bash 输出的中文能正确显示，
末行 `chcp 936` 是为了让 cmd 自己的 `pause` 提示不乱码——
这两行本身都是 ASCII，所以安全。

### 写新 `.bat` 时的模板

```bat
@echo off
rem Pure ASCII only -- NOT EVEN IN COMMENTS (see 03-docs for why)
setlocal
bash "%~dp0some-script.sh"
chcp 936 >nul
echo.
pause
```

校验器会检查这条规则（第 ⑥ 项），违反即**拦截提交**。

## 五、改规则

**只改一个地方**：`04-脚本/check-structure.sh` 顶部的「规范定义」段。

```bash
TOP_DIRS=( ... )      # 顶层必需目录
SUB_DIRS=( "02-数据|原始|处理后" )   # 子目录要求，格式 父|子|子
PROJ_DIRS=( src docs data out )      # 项目内必需目录
PROJ_FILES=( README.md )             # 项目内必需文件
ROOT_WHITELIST=( ... )               # 根目录白名单
BAD_NAMES=( ... )                    # 命名词黑名单
```

改完同步更新本文的规则清单表，然后跑一次 `check-structure.sh` 确认没有误伤。

## 六、换机器 / 新克隆后

钩子不在版本库里自动生效（`core.hooksPath` 是本机配置），需要跑一次：

```bash
git clone https://github.com/qingwangx/aiwork.git
cd aiwork
bash 04-脚本/install-hooks.sh
```

不跑也能用，只是失去了提交时的本地拦截——GitHub Actions 那一层仍然有效。

## 七、已知覆盖不到的情况

诚实说明这套机制的边界：

- **工作空间之外的目录**不受任何约束。这套规范只对 `F:\AIwork` 生效。
- **钩子可被 `--no-verify` 绕过**——所以才需要 CI 兜底。
- **只校验结构，不校验内容**。`README.md` 存在 ≠ 写得好；
  目录建了 ≠ 文件放对了地方。内容质量仍靠 `AGENTS.md` 的约定与人工把关。
- **CI 只在推送后生效**，拦不住本地历史被写乱，只能事后报警。
