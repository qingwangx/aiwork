# AIwork 工作区

> 第一个 GitHub 仓库，用于同步 AI 工作创作及产出
> Hermes AI 助手的默认工作空间 · `F:\AIwork`
> 建立日期：2026-09-29

## 这是什么

一个为「和 AI 一起干活」设计的文件夹体系。核心思路只有三条：

1. **一个入口**：所有活儿都从 `F:\AIwork` 开始，不再满硬盘找文件。
2. **各归其位**：数据、脚本、文档、成果各有固定去处，找东西不用猜。
3. **干净可清**：临时区随时删，原始数据永不改，根目录不堆东西。

## 五分钟上手

| 我要做什么 | 放哪里 |
|---|---|
| 新建一个任务/项目 | `01-项目/` 下建目录（或双击 `04-脚本/新建项目.bat`） |
| 下载了一堆原始数据 | `02-数据/原始/` |
| 写了个清洗脚本 | 项目内 `src/`；若通用则移到 `04-脚本/` |
| 最终要交给领导/客户的文件 | `06-产出/` |
| 网上找的参考资料 | `07-参考资料/` |
| 临时试验、造个草稿 | `09-临时/` |
| 项目干完了 | 整个目录移到 `08-归档/2026-项目名/` |

## 三条铁律

1. **`02-数据/原始/` 只读** —— 修改原始数据是不可逆的错误。
   要处理就在 `02-数据/处理后/` 生成新文件。
2. **`06-产出/` 才是成品** —— 中间文件不要放这里，避免拿错版本给人。
3. **不用"最终版"命名** —— 用 `-v1`、`-v2` 或日期前缀。

## 命名规范

```
20260929-桥梁监测方案-v2.md      ← 日期 + 内容 + 版本
桥梁监测/                        ← 目录用名词，不用动词
```

- 多词用连字符 `-`，**不用空格**（空格会让命令行各种踩坑）
- 中文文件名没问题，但在脚本里引用时记得加引号：`"02-数据/原始/数据.csv"`

## 给 AI 的约定

根目录的 `AGENTS.md` 是写给 Hermes 看的规则文件——它规定了「数据不可变」
「产物落位」「跨项目脚本沉淀到 `04-脚本/`」等行为。在 `F:\AIwork` 下开新会话时，
这些约定会自动生效，不需要每次重复交代。

要调整 AI 的行为习惯，直接改 `AGENTS.md` 即可。

## 版本控制

`F:\AIwork` 已初始化为 git 仓库（分支 `main`）。改动有记录，误删可回滚。

```bash
git status              # 看改了什么
git log --oneline       # 看历史
git checkout -- <文件>   # 撤销未提交的修改
git revert <提交号>      # 回滚已提交的内容（推荐，安全）
```

## 结构护栏（怎么保证不乱）

规范不靠自觉，靠四层机制递进保证，越往后越硬：

| 层级 | 机制 | 何时生效 | 能否绕过 |
|---|---|---|---|
| **L1 约定** | `AGENTS.md` | AI 每次会话自动加载 | 能（AI 可能忘） |
| **L2 模板** | `新建项目.sh` | 建项目时的唯一入口 | 能（可手建目录） |
| **L3 校验** | `检查结构.sh` | 手动 / 钩子 / CI 调用 | 能（没人跑就不跑） |
| **L4 强制** | pre-commit 钩子 + GitHub Actions | 每次提交、每次推送 | 本地可 `--no-verify`，**CI 不能** |

思路：L1/L2 让「正确做法」成为最省事的做法，L3 让问题当场可见，
L4 让问题进不了历史。本地留了后门（避免紧急提交被误伤），
远端 CI 兜底保证 `main` 永远合规。

```bash
bash 04-脚本/新建项目.sh 项目名     # 建项目（唯一入口，自动合规）
bash 04-脚本/检查结构.sh            # 检查结构
bash 04-脚本/检查结构.sh --fix      # 检查并自动补齐缺失的目录/README
bash 04-脚本/安装钩子.sh            # 新克隆后装一次钩子
```

完整规则清单见 `03-文档/目录结构规范.md`。
